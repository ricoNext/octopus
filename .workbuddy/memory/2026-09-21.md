# 2026-09-21

## octopus 应用内更新功能（分支 feat/auto-update，commit 8916313）

- 接入 `@tauri-apps/plugin-updater` 2.12.0 + `@tauri-apps/plugin-process` 2.3.1（前端 + Rust 两侧）。
- `src-tauri/tauri.conf.json`：`bundle.createUpdaterArtifacts: true`，`plugins.updater.endpoints` 指向 `https://github.com/ricoNext/octopus/releases/latest/download/latest.json`；**pubkey 是占位符 `REPLACE_WITH_TAURI_SIGNING_PUBLIC_KEY`，待用户手动填入**。
- 新增 `src/lib/updater.ts`（useAppUpdater hook）与 `src/components/UpdateDialog.tsx`（更新弹窗，含下载进度、changelog 轻量渲染）。
- `App.tsx`：启动 4 秒后静默检查；SettingsPage 新增「关于与更新」分区（当前版本 + 手动检查）。
- 新增 `.github/workflows/release.yml`：tag push 触发 tauri-action 构建，更新说明从 `changelog.md` 顶部段落用 awk 提取写入 Release body → latest.json notes。
- 发布前用户需做的事：`bunx tauri signer generate -w ~/.tauri/octopus.key` 生成密钥，公钥填入 tauri.conf.json，私钥配到 GitHub Secrets（TAURI_SIGNING_PRIVATE_KEY / TAURI_SIGNING_PRIVATE_KEY_PASSWORD）。
- 验证：`bun run build`（tsc + vite）与 `cargo check` 均通过。

### 踩坑记录

- 在 React hook 内命名局部函数 `check` 会遮蔽 `@tauri-apps/plugin-updater` 的 `check` 导入，导致自递归类型错误；导入别名 `checkForUpdate` 解决。
- 本会话中 Edit 工具出现过"报告成功但实际未落盘"的情况（SettingsPage 签名、type 导入、静默检查 effect 三处），构建报错后才暴露，需警惕并重新应用。

## 清理 paths.rs 死代码（slugify）

- `src-tauri/src/paths.rs` 的 `slugify`/`is_kept`/`is_han` 是早期"中文显示名→目录名"方案遗留：slugify 保留汉字，但 `create_worktree` 的 `is_valid_branch_name` 只接受 ASCII，永远接不进流程，全库无调用方。
- 删除三个函数 + slug 测试 + Cargo.toml 中仅被它使用的 `unicode-normalization` 依赖。
- 验证：`cargo check` 零 warning，`cargo test --lib` 5 个测试全过。
