# 全局任务看板与 Agent 执行设计

日期：2026-10-10

状态：本轮需求访谈记录；产品决策已逐项确认，技术对接与实现细节仍需验证。

## 目标与边界

为个人开发工作提供全局任务看板，将任务描述、Agent 执行、过程对话、文件变更和人工验收串起来。

任务独立于侧栏的 Git 项目及工作树菜单。创建任务不要求选择已登记项目或工作树，也不自动创建工作树。任务通过系统目录选择器关联任意多个本地目录，包括普通目录和已有工作树。

第一版允许多个任务同时执行，即使目录重叠也不强制排队。同一文件的并发修改检测、冲突处理与精确变更归属列入后续待办。

## 已确认的产品决策

### 创建与编辑

创建任务需要：

- 标题。
- 目标描述。
- 验收标准。
- 约束条件。
- 从设置模块已配置的 Agent 中选择一个执行者。
- 通过系统目录选择器关联本地目录。
- 指定一个主工作目录，默认取第一个选中的目录，创建时可调整。

所有关联目录默认可读写。Agent 在主工作目录启动，其他目录作为附加工作目录传入。

创建后，Agent 选择固定。首次运行前可以编辑任务内容、目录和主工作目录；首次运行后保留原始任务信息，通过对话补充要求并保留变更记录，关联目录锁定。

### 看板

提供全局看板，支持按关联目录筛选，不要求任务归属于一个 Git 项目。

固定五个阶段，顺序如下：

| 阶段 | 含义 | 主要操作 |
| --- | --- | --- |
| 待运行 | 已创建，尚未启动执行 | 编辑、运行 |
| 执行中 | Agent 正在处理任务 | 查看过程、补充要求、停止 |
| 待处理 | 执行暂时无法继续，需要处理 | 回复、继续、查看失败原因后重试 |
| 待验收 | Agent 已提交结果，等待用户检查 | 查看变更、确认完成、提交修改意见 |
| 已完成 | 用户已确认完成 | 查看任务及历史结果 |

只允许修改列名。阶段含义、显示顺序固定，不支持增加列、调整列顺序或拖动卡片。

“待处理”卡片必须显示具体原因：等待回复、已停止、执行失败。该阶段是执行流程的分支，并非每个任务都必须经过的步骤。

阶段流转由用户操作和 Agent 事件驱动；重命名列不影响内部状态含义。

### 运行与对话

- 点击“运行”启动创建任务时选定的 Agent。
- 执行上下文包含目标、验收标准、约束条件及目录信息。
- 任务详情提供对话界面，用户可查看过程并补充要求。
- Agent 提问时进入待处理，标明等待回复；用户回复后继续执行。
- 用户可以停止执行，保留对话和已修改文件。
- 继续时优先恢复原 Agent 会话；无法恢复时明确提示，不伪装成无损恢复。
- 同一任务的继续、重试和修改意见形成执行历史；多个任务之间可并行。

### 验收

Agent 提交工作结果后进入待验收，由用户决定任务是否完成。

详情提供结果摘要、文件变更清单和文件差异查看。用户可以：

- 确认完成：进入已完成。
- 提交修改意见：立即沿用当前任务上下文继续执行，完成后再次进入待验收。

进程退出本身不代表任务已完成，也不充分证明任务可以验收。需要区分 Agent 提交结果、主动停止和异常退出。

### 退出应用

退出时若存在运行中的任务，提示用户选择后台继续，或停止任务后退出。

后台继续时，任务不应依赖窗口或前端进程存活；重新打开应用后恢复显示。遇到需要回复或验收的情况，保留状态并等待用户处理。停止后退出则保留任务历史和文件修改，之后由用户继续。

## 状态流转

| 当前阶段 | 事件或操作 | 目标阶段 |
| --- | --- | --- |
| 待运行 | 点击运行且执行成功启动 | 执行中 |
| 待运行 | 启动失败 | 待处理：执行失败 |
| 执行中 | Agent 请求用户回复 | 待处理：等待回复 |
| 执行中 | 用户停止，执行已停止 | 待处理：已停止 |
| 执行中 | 执行异常 | 待处理：执行失败 |
| 待处理：等待回复 | 用户回复并恢复执行 | 执行中 |
| 待处理：已停止 | 用户继续并成功恢复执行 | 执行中 |
| 待处理：执行失败 | 用户重试并成功启动 | 执行中 |
| 执行中 | Agent 提交工作结果 | 待验收 |
| 待验收 | 用户提交修改意见且成功继续执行 | 执行中 |
| 待验收 | 用户确认完成 | 已完成 |

启动、继续、停止期间显示操作中的反馈，避免尚未完成实际操作就显示错误的阶段。恢复或继续失败时保留意见和历史，并显示失败原因。

## 与 Agent 设置模块对接

用户负责后续的 Agent 配置能力；任务模块消费其配置，不另建一套配置编辑入口。

仓库已有《Agents Settings MVP》设计及相关设置代码，现有设计主要覆盖目录、启用状态、命令、参数、环境变量和终端启动。该设计明确将任务文本注入及状态钩子排除在设置模块第一期范围之外。

因此，任务内对话与生命周期需要独立的执行适配能力。复用启动命令并不等于已经实现完整任务执行。

以下是建议的对接契约，属于实现约束，尚未代表已验证的 Agent 能力：

| 能力 | 任务模块需要的数据或行为 |
| --- | --- |
| 读取配置 | 稳定的配置标识、显示名称、启用状态、启动参数及可用性 |
| 启动 | 任务上下文、主目录、附加可写目录，返回执行和会话标识 |
| 输出事件 | 过程消息、请求回复、提交结果、错误和停止确认 |
| 发送消息 | 将用户回复及修改意见交给对应会话 |
| 停止 | 终止当前执行并反馈结果，保留对话和文件 |
| 恢复 | 按会话标识恢复，或明确报告无法恢复 |
| 后台重连 | 查询执行状态，恢复事件与消息展示，避免重复启动 |

候选 Agent 来自设置模块；本次访谈没有新增或锁定具体工具清单。实现时必须核实相应工具对这些能力的支持，不能仅从进程是否存在推断其是否等待回复或已经提交结果。

## 建议的数据与界面组织

本节为便于实现提出的方案，具体字段及布局可在实现阶段调整。

- 全局任务入口：看板、按目录筛选、新建任务。
- 创建界面：任务内容、Agent 选择、多目录选择、主目录标记。
- 任务详情：任务信息、阶段及原因、操作按钮、对话、结果摘要、变更清单与差异。
- 阶段设置：仅修改五列的显示名称。

任务需独立持久化：任务标识、原始内容、Agent 配置标识、目录集合、主目录、阶段、待处理原因、首次启动时间与创建更新时间。

执行历史需区分任务与每轮执行，保存会话标识、消息、阶段事件、停止或失败原因以及结果。任务存在的时间可以长于任何一轮 Agent 执行。

## 实现前需要验证的技术细节

以下属于工程验证项，不应当被描述为已实现的能力：

1. 对接 Agent 配置接口，并验证选定工具的结构化消息、输入、停止、恢复和附加目录支持。
2. 核实现有守护进程能否承载任务会话、后台运行与重连；系统重启后的进程恢复不等同于退出界面后的后台继续。
3. 为普通目录及 Git 目录确定差异基线。不能把仓库已有未提交修改直接当作本任务生成的修改；并发场景下不承诺精确归属。
4. 覆盖新增、删除、修改文件的展示；二进制、大文件、缺失目录和不可读取文件需要明确反馈。
5. 明确设置中配置被删除、禁用或修改后的运行与恢复行为；保持任务绑定的 Agent 身份，不静默换用其他工具。

## 第一版验收场景

1. 不登记项目或工作树，也能创建关联多个普通本地目录的任务，选定主目录及已配置 Agent。
2. 首次运行前可编辑内容与目录；首次运行后目录锁定，后续要求通过对话保留。
3. 多个任务可同时运行，关联目录重叠不触发自动排队。
4. Agent 提问后卡片进入待处理并标明原因，回复后继续执行。
5. 停止保留历史与文件；继续成功或恢复失败均有明确反馈。
6. Agent 提交结果后进入待验收，显示摘要、变更及差异；人工确认后才完成。
7. 验收时提交修改意见会立即继续，之后可再次验收。
8. 退出时可选择后台继续或停止；重新打开后状态与实际执行情况一致。
9. 重命名列不改变流转含义及顺序，界面不提供卡片拖动或自定义新阶段。

## 后续待办与范围外事项

- 同一文件的并发修改检测、冲突处理及精确变更归属。
- 任务中途更换 Agent。
- 自定义阶段及流转规则。

本轮没有确认列表视图、任务依赖、多人协作、自动创建工作树、发布或合并代码等功能，不纳入第一版承诺。
