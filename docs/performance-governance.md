## PERF-001：快照生成按工作树重复启动 Git 进程

- 优先级：P0
- 状态：待治理
- 影响范围：应用启动、创建工作树、删除工作树、移除项目、刷新快照
- 相关代码：
  - `src-tauri/src/store.rs` 的 `Store::snapshot`
  - `src-tauri/src/store.rs` 的 `Store::reconcile`
  - `src-tauri/src/commands.rs` 的 `init_state`、`load_snapshot`

### 问题描述

`Store::snapshot` 遍历每个工作树时都会调用一次 `git worktree list`。同一项目的多个工作树会重复执行完全相同的 Git 命令。

如果一个项目包含 20 个工作树，仅生成一次快照就可能启动约 20 个 Git 子进程。启动阶段还会在 `init_state` 和 `load_snapshot` 中重复执行 `reconcile` 和状态保存。

### 治理建议

- 每次生成快照时，每个项目只执行一次 `git worktree list`。
- 使用以项目 ID 为键的临时查询结果，批量判断工作树是否存在。
- 合并启动阶段重复的 `reconcile` 和 `save`。
- 避免在循环中重复执行路径规范化和项目查找。

### 验收标准

- [ ] 一次快照生成最多为每个有效项目执行一次 `git worktree list`。
- [ ] 工作树数量增长不会线性增加同一项目的 Git 子进程数量。
- [ ] 启动阶段不存在重复的完整 `reconcile`。
- [ ] 保持现有路径丢失和工作树状态判断行为不变。
- [ ] 添加包含多个项目、多个工作树的单元测试或基准测试。

## PERF-002：PTY 数据使用 JSON 数字数组全局广播

- 优先级：P0
- 状态：待治理
- 影响范围：终端大量输出、构建日志、测试日志、长时间运行命令
- 相关代码：
  - `src-tauri/src/pty.rs` 的 PTY 读取线程和 `pty-data` 事件
  - `src/components/TerminalPane.tsx` 的 `pty-data` 监听

### 问题描述

后端每次最多读取 4096 字节 PTY 数据，并将 `Vec<u8>` 通过全局 Tauri 事件发送。字节数组会被序列化成 JSON 数字数组。

当前格式的简单测量结果：

- 原始数据：4096 字节
- JSON 事件数据：约 14678 字节
- 传输放大：约 3.58 倍

每个终端组件都会监听同一个全局事件。终端数量增加后，每个数据块都会触发所有监听器，再由前端根据终端 ID 过滤。

### 治理建议

- 优先评估 Tauri Channel 或面向单个会话的数据通道。
- 如果仍需文本协议，评估 Base64 等比 JSON 数字数组更紧凑的编码。
- 前端只注册一个 PTY 数据监听器，再根据会话 ID 分发。
- 对连续小数据块进行安全合并，降低事件发送频率。
- 保证多字节 UTF-8、ANSI 控制序列和任意字节流不会因分块损坏。

### 验收标准

- [ ] 不再把 PTY 字节流序列化为 JSON 数字数组。
- [ ] 全局 PTY 数据监听器数量不随终端数量线性增长。
- [ ] 高频输出时 IPC 事件数和传输字节数有明确下降。
- [ ] 中文、ANSI 颜色、交互式命令和大段粘贴均正常。
- [ ] 至少使用一个持续高频输出命令完成真实运行验证。

### 验证记录

基线：4096 字节样本序列化后约为 14678 字节，约放大 3.58 倍。

## PERF-003：访问过的终端长期常驻

- 优先级：P1
- 状态：待治理
- 影响范围：长时间使用、频繁切换项目和工作树、多个后台任务同时运行
- 相关代码：
  - `src/App.tsx` 的 `visited`、`visitedReady`、`visitedMains`
  - `src/components/TerminalPane.tsx`

### 问题描述

所有访问过的终端都会保留在页面中，仅通过 `invisible` 隐藏。每个终端持续持有：

- xterm 实例及默认回滚缓冲区
- PTY 数据和退出事件监听器
- ResizeObserver 等前端资源
- 后端 Shell/PTY 会话

终端访问数量持续增长时，内存、监听器、后台进程和事件分发成本也会增长。

### 治理建议

- 明确产品需要的是“终端会话持久化”还是“终端渲染器持久化”。
- 后端会话可以保留，但前端隐藏终端可按 LRU 策略释放渲染资源。
- 为常驻终端设置合理上限，超出后释放最久未使用的会话或渲染器。
- 在 UI 中明确展示仍在后台运行的终端。

### 验收标准

- [ ] 访问终端数量持续增长时，前端 xterm 实例数量存在明确上限。
- [ ] 已释放终端不会继续接收和处理全局 PTY 事件。
- [ ] 产品要求保留的后台命令不会被意外终止。
- [ ] 连续切换至少 20 个终端后，内存和监听器数量不会无界增长。

## PERF-005：Diff 无大小限制、重复请求且存在响应竞态

- 优先级：P1
- 状态：待治理
- 影响范围：大型提交、大量二进制变化、频繁切换工作树
- 相关代码：
  - `src-tauri/src/workspace.rs` 的 `get_diff`
  - `src-tauri/src/commands.rs` 的 `get_diff`
  - `src/App.tsx` 的 `refreshDiff` 和相关 Effect
  - `src/components/DiffPane.tsx`

### 问题描述

当前会执行完整的 `git diff <start_from>`，然后把全部输出依次保存在 Git 子进程输出、Rust String、IPC 消息、React state 和 DOM 文本中。

同时存在以下问题：

- 没有字节数或行数上限。
- React 直接在一个 `<pre>` 中渲染全部文本。
- Effect 依赖整个 `selectedWorktree` 对象，新快照可能触发不必要的重复请求。
- 快速切换工作树时，旧请求可能晚于新请求返回并覆盖当前结果。
- Git diff 执行期间持有全局 Store 锁。

### 治理建议

- 优先返回文件级概要，再按需读取具体文件 Diff。
- 为单次 Diff 设置字节数和行数上限，并向用户显示截断提示。
- 使用请求序号或取消机制忽略过期响应。
- Effect 依赖工作树 ID、状态和 missing 等稳定的原始字段。
- 在执行 Git 命令前复制所需路径和分支信息并释放 Store 锁。
- 大文本展示评估分块或虚拟化方案。

### 验收标准

- [ ] 大型 Diff 不会无限制进入 IPC 和 React state。
- [ ] 快速切换工作树时，旧响应不能覆盖当前工作树结果。
- [ ] 无关快照更新不会重复执行当前工作树的 Git diff。
- [ ] Git diff 运行期间不持有全局 Store 锁。
- [ ] 使用大型文本文件和大量变更文件完成压力验证。

## PERF-006：慢速 Git 操作长期持有全局 Store 锁

- 优先级：P1
- 状态：待治理
- 影响范围：创建、重试、检查仓库、分支列表、Diff、删除工作树
- 相关代码：
  - `src-tauri/src/commands.rs`
  - `src-tauri/src/workspace.rs`

### 问题描述

多个命令会先获取全局 `Mutex<Store>`，然后在锁内执行 Git 子进程或文件系统操作。例如创建工作树时，锁会覆盖整个 `git worktree add` 执行过程。

虽然创建流程存在按项目的 `CreateGuard`，但全局 Store 锁仍会让不同项目的相关操作互相等待。

### 治理建议

- 在锁内完成参数读取和状态预提交后释放锁。
- 在锁外执行 Git 和慢速文件系统操作。
- 完成后重新获取锁，校验状态并提交结果。
- 明确处理中、成功和失败状态，避免释放锁后出现状态覆盖。
- 保留同一项目的并发保护，同时允许互不相关的项目并行执行。

### 验收标准

- [ ] 慢速 Git 子进程执行期间不持有全局 Store 锁。
- [ ] 一个项目创建工作树时，其他项目仍可读取快照或执行只读操作。
- [ ] 同一项目不会并发创建冲突的工作树。
- [ ] 失败、中断和应用退出后的状态仍可正确恢复。

## PERF-007：PTY resize 存在重复调用和高频 IPC

- 优先级：P2
- 状态：待治理
- 相关代码：`src/components/TerminalPane.tsx`

### 问题描述

- `ptyOpen` 已携带行列尺寸，但打开后仍无条件调用一次 `ptyResize`。
- `ResizeObserver` 每次回调都会执行 `fit.fit()` 并发送 IPC。
- 没有尺寸去重、帧合并或防抖。

### 治理建议

- 使用 `ptyOpen` 返回值区分新建会话和已有会话。
- 新建会话不重复发送相同尺寸的 resize。
- 记录上一次行列值，仅尺寸实际变化时发送。
- 使用 `requestAnimationFrame` 合并同一帧内的 ResizeObserver 回调。

### 验收标准

- [ ] 同一尺寸不会重复发送 `pty_resize`。
- [ ] 连续拖动窗口时，每帧最多执行一次 fit 和 resize。
- [ ] 切换隐藏终端时尺寸恢复正常。

## PERF-008：侧栏重复遍历全部工作树

- 优先级：P2
- 状态：待治理
- 相关代码：`src/components/Sidebar.tsx`

### 问题描述

侧栏在 Effect 和渲染阶段都按项目执行 `worktrees.filter`，整体复杂度接近项目数乘以工作树数。当前数据规模较小时影响有限，但属于容易消除的扩展性问题。

### 治理建议

- 使用 `useMemo` 一次性构建 `Map<projectId, Worktree[]>`。
- 项目计数和渲染共用同一个分组结果。
- 仅在实际出现大量项目或侧栏渲染成为热点时考虑列表虚拟化。

### 验收标准

- [ ] 一次渲染只遍历一次完整工作树列表完成分组。
- [ ] 折叠、展开和新增工作树行为保持不变。

## PERF-009：异步事件监听存在卸载竞态

- 优先级：P2
- 状态：待治理
- 相关代码：`src/components/TerminalPane.tsx`

### 问题描述

事件监听通过异步 `listen(...).then(...)` 注册。如果组件在 Promise 返回前卸载，Effect 清理函数可能看不到最终的取消监听函数，导致监听器残留。开发模式下 React StrictMode 的重复挂载更容易暴露此类问题。

### 治理建议

- 在 Effect 中维护取消标记。
- 如果监听注册完成时组件已经卸载，立即调用返回的 unlisten。
- 更推荐结合 PERF-002，改为应用级唯一监听器。

### 验收标准

- [ ] 组件快速挂载和卸载不会残留事件监听器。
- [ ] React StrictMode 下不会出现重复 PTY 数据处理。
- [ ] 删除工作树后不再收到对应终端的前端事件回调。
